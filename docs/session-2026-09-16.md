## DL-012 — Branch Diagnosis & Growth Origin (핵심 원칙)

> **"증상으로 칸을 만들지 않는다. 가장 싼 구조 변경만 고른다.
> 판정이 안 바뀌면 노드가 아니다."**

### 배경
- `promotion.py` 가 `UNMAPPED_SOURCE_TYPE → CLASS`,
  `RULE_COVERAGE → SCOPE` 로 자동 확정 → **클래스 폭발 위험**
- 3개 엔진(GPT/Grok/재확인) 독립적으로 같은 결론

### 확정 사항
1. residual_type = **증상**, candidate_type = **진단**
2. candidate_type = `{ALIAS, MAPPING, CLASS, SCOPE, NONE}`
   - 비용 순서: ALIAS < MAPPING < CLASS < SCOPE
3. `NO_ONTOLOGY_CHANGE` 공식 허용 (LLM이 "만들지 마" 답할 권리)
4. 승격 gate = **반복성 + 판정 가치(decision_gain)**
5. `growth_origin = {TOP_DOWN, BOTTOM_UP}`
   - BOTTOM_UP: residual 경로
   - TOP_DOWN: 법령 개정 diff (Phase 2/3 이후)
6. 92-class 선제 확정 금지. backbone + 자가확장.

### DB 반영 (0066 마이그레이션)
- `candidate_type` CHECK 확장: `NONE` 추가
- `branch` 컬럼 신규: `ONTOLOGY | RULE | REPAIR`
- `growth_origin` 컬럼 신규: `TOP_DOWN | BOTTOM_UP`
- `decision_gain` 컬럼 신규 (nullable)

### promotion.py 반영
- `_CANDIDATE_TYPE_MAP` **삭제**
- `_BRANCH_MAP`: `UNMAPPED_SOURCE_TYPE → ONTOLOGY`, `RULE_COVERAGE → RULE`
- `candidate_type = 'NONE'` (미정), `growth_origin = 'BOTTOM_UP'`
- `rationale` 프리픽스: `[ONTOLOGY]` / `[RULE]`
- 옵션 A: promotion은 **Ollama 안 부름** (규칙 기반 브랜치 태깅까지)
